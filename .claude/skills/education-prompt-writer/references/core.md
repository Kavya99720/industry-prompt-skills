# Education core: rules that apply to EVERY workflow

Built from docs/shared/new-industry-template/core.template.md, with the retail package as the pattern. IDs are unique across this file and the workflow files (R-01 to R-42 here; workflow rules continue from R-43). Every rule has a Severity, a Section placement and a Scope (when it applies and when it does not). A fixed phrase never overrides a safety rule or a required line. Rule IDs never appear in the Instructions; they live in the sources only.

Principle: safety rules from our brief win; platform reality (tools, live-tested flow) wins where the platform fixes how something works. Where the grill-me leaves something open, it is listed in the brief's open questions and not guessed.

v1 is VOICE ONLY. There is no chat wording and no chat channel (chat is a later option).

Fixed-line check note: scripts/check_fixed_lines.py reads every `say exactly` line in this file and in the selected workflow files. Outbound-only fixed lines therefore live in the outbound frame (workflow 09), never here. A row that names `booking_tool`, `send_link`, `calls_recorded` or `confirmation_channels` is required only when ALL the settings it names are on; a row marked `[booking_tool: off]` is required only when the tool is off.

## Tools

Confirmed on the platform: `change_language`, `transfer`, `end_call`. Optional, from config, default OFF: `booking_tool` (a demo class or counselling slot; the platform's `booking` tool is built around appointments, so whether it fits a demo class is an open question in the brief), `send_link` (an approved link goes out through the After-the-call trigger). Callback is a setting, default ON: it means the agent collects name, number and reason and says the team will call; with callback OFF the agent never offers or collects one and gives the office hours and phone instead.

There is NO in-call send tool: confirmations and links go out through the After-the-call trigger (docs/shared/confirmation-flow.md), so the agent never says a link or confirmation "has been sent". There is NO student lookup, fee lookup, results lookup, payment, admission or refund tool: the agent can only give published facts or note a request for the team.

Not selected, never assumed: student record lookup, fee dues lookup, payment tool, admission or seat tool, certificate tool, CRM write. What a tool returns is stated only as returned.

## Intake (what the skill asks first)

## Routing (who a transfer goes to)

Only targets given at intake exist. A topic whose named team was not given goes to the main target; with no target at all, the agent takes a callback (callback ON) or gives the office hours and phone (callback OFF). The agent never invents a team or a desk.

| Topic | Target | Priority |
|---|---|---|
| Admissions, courses, batches, documents, bookings, scholarship questions, hostel, certificates and records, online-class help | admissions | Normal |
| Fees, payments, refunds, concessions | accounts | Normal |
| Transport | transport | Normal |
| Counselling, exam stress, course guidance | counsellor | Normal; self-harm and distress High |
| Complaints, ragging, harassment, bullying, a child-safety concern, a legal question, a journalist or regulator | grievance (the anti-ragging contact for ragging) | High |
| A payment problem or a suspicious payment or admission offer | accounts | High |
| Asks for a person (no topic) | main target | Normal |

High priority means: in the callback request, say it is high priority.

## Confirmation and link lines

Scope as in docs/shared/confirmation-flow.md: once, after the main action succeeded or a link was requested; not on failure, emergency, handoff, voicemail or when the caller is done. Only enabled channels; the After-the-call trigger sends; never say it was sent.
