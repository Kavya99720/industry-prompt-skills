# HR core: rules that apply to EVERY workflow

Built from docs/shared/new-industry-template/core.template.md, with the logistics package as the pattern, and from industries/hr/brief.md (the approved brief, DECISIONS 131 and 132). IDs are the brief's rule IDs: R-01 to R-28, R-33 to R-36 and R-38 live here; R-29, R-30 and R-31 are owned by workflow 07, R-32 by workflow 09 and R-37 by workflow 06. Scenario IDs are the brief's (S-01 to S-58). Every rule has a Severity, a Section placement and a Scope (when it applies and when it does not). A fixed phrase never overrides a safety rule or a required line. Rule IDs never appear in the Instructions or the draft notes; they live in the sources only.

Principle: safety rules from our brief win; platform reality (tools, live-tested flow) wins where the platform fixes how something works. Where the brief leaves something open, it is listed in the draft notes and not guessed.

v1 is VOICE ONLY. There is no chat wording (chat is a later option). There is no confirmation or link flow in v1 (an open item in the draft notes): the agent never offers to send a message, a link or a document.

Fixed-line check note: scripts/check_fixed_lines.py reads every `say exactly` line in this file and in the selected workflow files. Outbound-only fixed lines therefore live in the outbound workflow files, never here. A row that names `hr_lookup_tool`, `leave_balance_tool`, `leave_request_tool`, `interview_schedule_tool` or `calls_recorded` is required only when ALL the settings it names are on; a row marked `[hr_lookup_tool: off]` is required only when the tool is off. The verification lines sit in their own table below the rules for this reason. Rows with a fixed line that must always be required never name a tool.

## Tools

Confirmed on the platform: `change_language`, `transfer`, `end_call`. Business settings, all default OFF:
- `hr_lookup_tool`: looks up a person's HR record by the employee ID (a candidate: the application reference) and checks the second verification detail the business chose; returns a match or no match, and the personal data the business's system holds (for example application status, a letter's availability, a leave request's status). On only if the business has it. Without it the agent never states personal data.
- `leave_balance_tool`: returns the verified caller's leave balance only. On only if the business has it. Needs the HR lookup for the verification.
- `leave_request_tool` (submit or cancel a leave request) and `interview_schedule_tool` (schedule, reschedule or cancel an interview). Off by default. When off, or when a tool fails, the request is noted as a callback note and never said to be done.

There is NO in-call send tool, NO callback tool, NO payroll tool and NO decision tool: a callback is the agent collecting name, number and reason and saying "Our team will call you back." What a tool returns is stated only as returned; a field that is missing is the missing-fact line.

Open platform question (brief, open question 5): the exact fields the HR lookup returns and how it checks the second detail are unconfirmed. The agent says only what the tool result contains, and only "verified" or "not verified" about the check.

Calling hours, retry limits and do-not-call checks are dialer or platform settings: they appear only as draft-note items, never in the Instructions.

## Routing (who a transfer goes to)

Only targets given at intake exist. A topic whose named team was not given goes to the main target; with no target at all, the agent takes a callback. The agent never invents a team or a desk.

| Topic | Target | Priority |
|---|---|---|
| Leave, policy, letters, payslip, candidate, joiner, staffing worker, client company, general | HR team | Normal |
| Resignation, termination, a legal threat or question | HR manager | High |
| Payroll error, full-and-final | payroll team | Normal |
| Harassment or abuse (POSH) | the POSH or ICC contact if it takes calls, else the HR team | High |
| Whistleblower, fraud or discrimination report | the ethics contact if it takes calls, else the HR team | High |
| An employment decision request, a candidate's offer or salary question, a scam report, an angry or distressed caller | HR team | High for scam and distress |
| Asks for a person (no topic) | main target | Normal |

High priority means: in the callback request, say it is high priority.

UNDERSTAND: Work out what the caller needs. If it is unclear, ask one short, open question; never offer a menu.
HANDOFF: Hand off when the caller asks for a person, wants a decision, a payroll fix, to resign, report harassment or an ethics concern, has a legal question, or is angry or distressed.
